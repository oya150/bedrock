# Elasticsearch

Elasticsearch(이하 ES)를 쓰다 보면 "왜 이렇게 동작하지?"에서 막히는 때가 와요. 저장했는데 바로 안 보이거나 같은 검색어인데 곳마다 순위가 달라요. 샤드 수는 나중에 마음대로 바꾸지 못해요. 이런 일의 답은 대부분 ES 안의 자료구조와 알고리즘에 있어요.

이 갈래는 문서 한 건이 ES에 들어와서 검색되어 나가기까지를 따라가며 그 바닥까지 내려가요. ES를 처음 써 보는 분도 따라올 수 있게 썼어요. 본문은 ES 7부터 9까지 똑같이 맞는 내용만 담았고 버전마다 다른 것은 각주에 적었어요. 글에 나오는 숫자는 예시를 그대로 따라 셀 수 있는 값이에요.

| 편 | 주제 | 읽고 나면 알게 되는 것 |

| 2 | [분석기: ES가 글을 낱말로 자르는 방법](02-analyzer.md) | ES는 글과 검색어를 같은 분석기로 잘라요. 한국어는 nori로 형태소까지 잘라야 "환불"이 나와요. |
| 3 | [샤드와 라우팅: 문서가 갈 샤드를 정하는 계산](03-routing.md) | ES는 문서가 갈 샤드를 나머지 계산으로 정해서 샤드 수는 바꾸지 못하고 배수로 쪼개기만 해요. |

| 8 | [BM25: ES가 검색 결과에 점수를 매기는 방법](08-bm25.md) | ES는 검색어 낱말마다 드문 정도와 횟수 몫을 곱해 더하고 이 값을 샤드마다 따로 세서 순위가 바뀔 수 있어요. |
| 9 | [위 10개만 찾기: 문턱 아래 문서는 점수를 계산하지 않아요](09-top-k.md) | ES는 위 10개의 가장 낮은 점수를 문턱으로 삼아 넘을 수 없는 문서는 점수를 계산하지 않아요. |
| 10 | [doc values: 정렬과 집계가 읽는 문서별 값 열](10-doc-values.md) | 정렬과 집계는 색인 때 적어 둔 "문서 → 값" 열을 읽어요. 글자 값은 순번으로 담아서 "100"이 "3"보다 앞에 서요. |

| 13 | [고유 사용자 수 어림하기: cardinality 집계와 HyperLogLog](13-cardinality.md) | 정확히 세면 본 ID를 다 들고 다녀야 해서 HyperLogLog는 통마다 가장 긴 앞 0 줄만 적어 수를 어림해요. |
| 14 | [노드가 꺼져도 데이터가 남는 까닭: 복제본과 체크포인트](14-replication.md) | 같은 샤드를 여러 노드에 두고 쓰기마다 번호를 매겨서 주 샤드가 꺼지면 빠짐없이 받은 복제본이 넘겨받아요. |
| 15 | [HNSW: 벡터 검색이 뜻이 비슷한 글을 빨리 찾는 길](15-hnsw.md) | 글을 벡터로 바꾸면 뜻으로 찾고 HNSW는 층을 쌓은 이웃 그물로 몇 개만 재서 빨리 찾지만 정답을 놓칠 수 있어요. |
